# ACLA_COVID19_mRNA_miRNA_Network_Analysis

Reproducibility package for the manuscript **“Paired mRNA–miRNA Network Analysis with A-CLA Reveals Cross-Modal Communities and Evidence-Prioritized Drug Candidates in COVID-19.”**

## Overview

This repository contains the executable and provenance code available for the paired whole-blood mRNA–miRNA analysis of GEO SuperSeries **GSE243219**. The workflow uses paired mRNA (**GSE243217**) and miRNA (**GSE243218**) data from 72 subjects: 35 COVID-19, 22 sepsis, and 15 healthy controls.

The primary analysis proceeds from processed GEO matrices through filtering, TMM normalization, differential expression, disease-adjusted partial Spearman association, paired disease-stratified bootstrap stability filtering, miRNA-target evidence annotation, network construction, topology-only A-CLA community detection, and post-community biological interpretation.

The final manuscript network contains **4,508 nodes** (4,467 mRNAs and 41 miRNAs) and **11,531 stable cross-modal associations**, including 1,978 independently target-supported associations. The final topology-only A-CLA analysis resolved **8 communities** with global modularity **Q = 0.5023**.

## Repository structure

- `src/` — accepted executable lineage available in the project archive, organized by analysis stage.
- `config/` — frozen/prespecified analysis parameters and database versions used in the manuscript.
- `data/` — data-acquisition instructions only; no GEO expression matrices are redistributed.
- `results/` — expected manuscript-scale summary values and guidance for generated outputs.
- `provenance/` — source inventory, SHA-256 manifest, and the authoritative D10 method/reporting record.
- `docs/` — workflow, reproducibility notes, code/data availability, and manual GitHub upload instructions.
- `tests/` — repository-integrity validator.
- `legacy/` — notes on excluded superseded/diagnostic branches.
- `experiments/` — notes on the prospectively evaluated but rejected signed A-CLA branch.

## Core workflow

1. Acquire and verify GSE243217/GSE243218 processed files.
2. Reconcile the 72 paired subjects and mature-miRNA identities.
3. Apply the prespecified expression filter and TMM normalization.
4. Fit the InMoose/edgepy quasi-likelihood differential-expression models.
5. Define the primary COV_vs_H feature universe (8,505 mRNAs; 41 mature miRNAs).
6. Estimate disease-adjusted partial Spearman associations in the 50 COVID-19/healthy subjects.
7. Apply 500 disease-stratified paired bootstrap replicates and retain stable associations.
8. Add DIANA-TarBase v9 / TargetScanHuman 8.0 / miRDB 6.0 evidence as annotations.
9. Construct the final signed bipartite network.
10. Apply the published A-CLA implementation to an all-edge topology-only projection.
11. Restore signed/regulatory semantics after community assignment and perform post-hoc characterization.
12. Perform enrichment and literature contextualization from the frozen community results.
13. Conduct the final drug–gene validation and VDGEI ranking as a documented interactive evidence-synthesis step; no local VDGEI program was executed.

Detailed parameters are in `config/analysis_parameters.yaml`.

## Important reproducibility note

The repository preserves the executed D0–D9 lineage and the recovered authoritative D10H–D10U source files from the original `09_ACLA` project directory. The exact publication-provenanced A-CLA source and the frozen D10I execution wrapper used for D10J are included byte-for-byte, with their executed SHA-256 hashes documented in `provenance/AUTHORITATIVE_D10_LINEAGE.md`.

The final communities were generated by the **original published A-CLA** on an unweighted all-association topology projection; the prospectively evaluated Signed A-CLA branch was not used for the biological partition. Signed-method development code is retained separately under `experiments/signed_acla_development/`. Superseded late-D10 corrections are retained under `legacy/d10_superseded_code/`.

D10V was a deterministic reporting stage and the recovered final D10V folder did not contain a standalone executable source file. Its PASS status, source/provenance maps, and reporting documentation are preserved under `provenance/d10_authoritative_runs/D10V/`.

The manuscript's final **VDGEI** scores were not produced by an executed local script. They were derived during an interactive AI-assisted evidence-review process using the prespecified scoring rubric documented in `src/11_drug_prioritization/README.md`. The repository therefore documents the rubric and provenance but deliberately does not fabricate an executable scoring program. Likewise, no dedicated manuscript figure-generation script was executed in the recovered project; figures were assembled from frozen analysis/reporting outputs, so `src/12_figures/` documents that limitation rather than supplying reconstructed plotting code.

## Environment

The executed workflow was Windows/PowerShell + Python. The project explicitly validated:

- Python 3.12.3
- InMoose 0.9.1

Other Python dependencies used by the included scripts are listed in `requirements.txt`. Where an exact version could not be recovered from the available archive, the package name is left unpinned rather than inventing a version.

## Reproducibility

The preserved source scripts intentionally retain their executed-stage logic and provenance checks. Some scripts contain assumptions about the original Windows project directory layout. Do not silently edit the archived source if exact provenance is required; instead adapt paths in a copy or wrapper and document the change.

Validate the package with:

```bash
python tests/validate_repository.py
```
